# Архитектура решения

## Контекст

Nixyon: Android-приложение, которое расшифровывает записи разговоров прямо на телефоне.
Запись с микрофона или импорт файла, распознавание речи, деление на говорящих, временные
метки реплик, просмотр, правка и экспорт работают без сети. Звук и текст никуда не
отправляются, облачных API нет.

Сеть нужна только лёгкой сборке APK, один раз: она скачивает модели с зеркала. В полной
сборке все модели лежат внутри APK, и приложение работает без интернета с первого запуска.

Языки речи: русский и английский, язык записи определяется сам или задаётся в настройках.
Языки интерфейса: русский и английский.

## Компоненты

### Приложение

- **Интерфейс:** HTML, CSS и JS без сборщика в `nixyon-app/ui`, тема одна, тёмная. Тексты
  только в словарях `nixyon-app/ui/locales/ru.json` и `en.json`; модуль ключей
  `ui/generated/i18n.js` строит `build.rs` при сборке, копия лежит в git для макета
  `preview/`. Устройство интерфейса описано в `nixyon-app/ui/DESIGN.md`.
- **Ядро приложения:** Rust на Tauri 2 в `nixyon-app/src-tauri`: команды для интерфейса,
  сборка расшифровки, правка, экспорт, хранилище с шифрованием, протокол встречи.
- **Плагин Android:** Kotlin в `nixyon-app/plugins/android/android/src/main/java`: запись,
  импорт, запуск моделей через sherpa-onnx, плеер, сохранение файлов и «Поделиться», языковая
  модель через llama.cpp (C++ в `src/main/cpp`). Модели, которые sherpa-onnx не загружает,
  считает Rust через JNI (`nixyon-app/plugins/android/src`).

### Крейты Rust

| Крейт | Что делает |
|---|---|
| `nixyon-core` | типы расшифровки, JSON, трейты движка и моделей |
| `nixyon-audio` | WAV, перевод в 16 кГц моно, выравнивание громкости, проверка качества записи |
| `nixyon-cluster` | кластеризация голосов, оценка числа говорящих, венгерский алгоритм |
| `nixyon-pipeline` | сборка расшифровки из результатов моделей, правка, поиск, статистика |
| `nixyon-render` | экспорт TXT, Markdown, SRT, JSON, DOCX и блоки протокола для PDF |
| `nixyon-locales` | проверка словарей интерфейса, подписи экспорта, модуль ключей для JS |
| `nixyon-ort` | модели на ONNX Runtime: модель голоса ReDimNet2, сегментация pyannote, возраст, эмоции |
| `nixyon-sherpa` | тот же конвейер на ноутбуке для замеров и утилита `transcribe` |
| `nixyon-metrics` | WER, CER, cpWER, DER |
| `nixyon-eval` | прогоны на наборах записей: `eval`, `quality_eval`, `stream_eval` |

### Конвейер на телефоне

1. **Вход.** Запись с микрофона в зашифрованный WAV или импорт файла через системный выбор
   (m4a, mp3, wav, ogg, opus, flac). Android раскодирует файл и сводит его в моно.
2. **Подготовка звука.** Перевод в 16 кГц моно, громкость приводится к -20 dBFS. Запись
   короче 1 с и тишина не обрабатываются, о клиппинге приложение предупреждает.
3. **Поиск речи.** Silero VAD режет запись на куски до 20 с с запасом 0,2 с с каждой
   стороны. Куски от 15 с режет второй VAD по звуку после шумоподавителя GTCRN.
4. **Язык.** В режиме «Авто» Whisper tiny слушает 5 кусков из разных частей записи.
   Английский выбирается, если за него больше половины ответов, иначе русский.
5. **Распознавание.** Русский: GigaAM v3 с пунктуацией, поиск по лучам с горячими словами
   (имена из библиотеки голосов и список из настроек). Английский: Parakeet TDT 0.6B v3,
   жадный поиск. Время каждого слова берётся из токенов.
6. **Кто говорит.** Нейросегментация pyannote блоками по 60 с показывает, когда звучит
   голос и где голоса накладываются. Эмбеддинги голоса считает ReDimNet2-B6. Число
   говорящих задаётся или оценивается само (до 8), похожие группы сливаются по косинусу
   0,7. Говорящий слова берётся по середине слова.
7. **Реплики.** Соседние реплики одного говорящего с паузой до 1 с склеиваются. Реплика с
   наложением голосов остаётся отдельной. Речь, где слышен голос, но текст не распознан,
   остаётся репликой с флагом `unclear`. Реплика, голос которой мало похож на её
   говорящего, получает флаг `speaker_unsure`.
8. **Имена и метки.** Имена по образцам голоса из библиотеки, эмоция реплики (GigaAM-Emo),
   «ребёнок или взрослый» у говорящего. Модели эмоций и возраста необязательные.
9. **Сохранение.** Расшифровка, центры голосов и запись хранятся зашифрованными в архиве
   встреч.
10. **Дальше по запросу.** Просмотр с плеером и переходом к реплике, правка (имя
    говорящего, слияние говорящих, текст, удаление реплики, повторное распознавание
    реплики), поиск, статистика, протокол встречи, экспорт.

Ход разбора виден на экране обработки, разбор можно отменить.

## Основные технические решения

- **Нейросегментация вместо деления по паузам.** pyannote видит смену говорящего без паузы
  и наложение голосов, кластеризация по кускам VAD этого не умеет. Запасная ветка по кускам
  VAD осталась для замеров (`eval --no-neural`).
- **ReDimNet2-B6 вместо CAM++.** На восьми проверочных диалогах путаница говорящих 16,3 %
  против 25,0 % у CAM++, число голосов верно в 7 записях из 8 против 5.
- **GigaAM v3 с пунктуацией.** Модель сразу даёт знаки препинания, заглавные буквы и числа
  цифрами, отдельная модель пунктуации не нужна.
- **Жадный поиск для Parakeet.** Поиск по лучам sherpa-onnx 2.0.1 терял фразы в куске из
  нескольких фраз: WER на английских диалогах 17,8-27,3 % против 4,0-6,3 % у жадного.
- **Языковая модель на одну задачу.** Qwen3.5-4B грузится на запрос и выгружается. Если
  свободно не меньше размера модели и ещё 1 ГБ, веса перекладываются под инструкции
  процессора, иначе читаются из файла. При нехватке памяти сначала отпускаются модели речи.
  Длинная встреча делится на части, протоколы частей сводятся в один.
- **Ускорение.** Распознавание, сегментация и модели голоса идут в столько потоков,
  сколько у телефона быстрых ядер (от 4 до 8), ядра выбираются по `cpu_capacity`. llama.cpp
  собран в вариантах под разные ядра arm64 и сам берёт лучший (dotprod, i8mm, SVE, SME).
  Языковую модель можно перевести на видеокарту через Vulkan: это сборка со свойством Gradle
  `nixyonLlmVulkan` и переключатель в настройках, по умолчанию выключено. Если видеокарта не
  нашлась или модель на ней не загрузилась, модель считает на процессоре.
- **Память.** Запись читается кусками и целиком в памяти не держится.
- **Один источник истины.** Внутренний JSON расшифровки (`nixyon-core`, версия формата 1),
  все экспорты строятся из него. Формат JSON-вывода из задания описан в
  [PROTOCOL.md](PROTOCOL.md).
- **Без `unsafe`, кроме JNI.** `unsafe_code` запрещён во всех крейтах, исключение только
  JNI-граница моделей, каждый блок объяснён комментарием `SAFETY:`.

## Зависимости

- Tauri 2 (`tauri` 2.12.5), Rust edition 2024, MSRV 1.95.
- sherpa-onnx 2.0.1 (aar для Android и статические библиотеки для ноутбука), ONNX Runtime
  из него же, крейт `ort` линкуется с той же библиотекой.
- llama.cpp тега `b12005`, собирается Gradle через CMake.
- Android: minSdk 24, targetSdk и compileSdk 37, только `arm64-v8a`, NDK 30.0.16248370.
- Версии и суммы SHA-256 моделей и библиотек закреплены в скриптах `scripts/fetch-*.sh`.

## Безопасность и приватность

- Вся обработка на устройстве, звук и текст не уходят в сеть.
- Хранилище шифруется AES-256-GCM, формат `NXSEAL01`: куски по 64 КиБ, в AAD каждого куска
  заголовок, номер куска и признак последнего. Ключ данных обёрнут ключом Android Keystore.
  Шифруются записи, расшифровки, протоколы, центры голосов, библиотека голосов и настройки.
- Вход по отпечатку пальца включается в настройках.
- Приложение обрабатывает только файлы из своих папок, ссылки раскрываются.
- Наружу через `FileProvider` открыта только папка экспорта, её чистит следующий экспорт
  и запуск приложения. Резервное копирование выключено (`allowBackup="false"`).
- Записи, расшифровки, образцы голоса и поисковые запросы в лог не пишутся.
- Модели сверяются с каталогом по размеру и SHA-256.
